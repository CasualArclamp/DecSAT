# DecSAT manual: Features and test status

This page lists each function of DecSAT and its test status. [Back to the README](../../README.md).

| Function | Status |
|---|---|
| Waterfall and spectrum of the full span. Zoom and pan. | ✅ |
| Carrier detection. DecSAT marks each carrier with its symbol rate. A finer analysis tells slow carriers (a 9.6 kS/s link in a 20 MS/s span) from CW tones and spurs. | ✅ |
| VFOs. You can draw, drag and resize a VFO. Click a carrier to claim it. Each VFO has one thread. | ✅ |
| **Identify**: blind symbol rate, roll-off, constellation, DVB-S2/S2X detection. | ✅ |
| **Survey**. DecSAT tries each clean carrier in the span in turn, a few at a time. It runs Identify, then the decoder of the carrier, with a time to lock. The list shows the outcome, the model, the contents and the payload of each carrier. You can save the list as CSV. | ✅ |
| DVB-S2/S2X PL demodulation: frame lock, and the MODCOD of each frame (ACM). | ✅ |
| Carrier recovery for Identify and DVB-S2 VFOs: a locked constellation, Es/N0 (the MER) and Eb/N0. | ✅ |
| **DVB-S → MPEG-TS** (EN 300 421). DecSAT finds the code rate, the rotation and the inversion blind. Then come Viterbi, RS and the same TS outputs. | ✅ |
| **TPC 2964 → IP / TS / voice** (Intelsat IESS-315 turbo product code, BPSK/QPSK/8PSK), and **Comtech TPC 7/8** (16K block), which was found from a live carrier. DecSAT finds the frame structure, the scrambling and the payload from the signal. The payloads are: HDLC → IP (Cisco HDLC, PPP, Frame Relay). Comtech EDMAC → bridged Ethernet → IP. MPEG-TS. MPEG audio frames (a programme feed: listen, record `.mp2`). E1. Comtech D&I++ voice (one timeslot or several). 64 kbit/s timeslots in HDLC packets. These timeslots carry the voice channels of a trunk, its IP, and the ADS-B and radar in it. | ✅ confirmed on live Comtech CDM-600L and CDM-570L carriers |
| **Q-Flex FastLink → data and voice** (Paradise, QPSK 0.710). The sync word, the (2880, 2048) LDPC code and the frame scrambler were all measured from a live carrier. Inside are the closed-network + ESC framing of Paradise and a 257-bit TDM multiplex (sixteen 8 kbit/s channels). DecSAT meters the channels live, so that speech shows. DecSAT assembles the G.728 voice of a call from its four channels. You can listen and record a `.wav`. For the 2–4 × faster links, DecSAT decodes the multiplex, its HDLC timeslot (bridged Ethernet → IP) and its G.728 calls. | ✅ decodes live Q-Flex links down to the speech of the calls, and also the IP of the faster links |
| **Viterbi → data**. The K = 7 code (IESS-308/309 SCPC, DVB-S) at rate 1/2–7/8. DecSAT finds the puncturing and the orientation blind, and follows them when the carrier turns. It also decodes **any other rate-½ convolutional code up to K = 10** on BPSK or QPSK. It reads the generators from the parity check that the stream satisfies (K = 9 (561, 753), K = 5, CCSDS-style inverted outputs …). Then the payload search, with or without differential decoding, looks for HDLC, TS, E1, D&I++, Paradise or IBS/SMS (IESS-309, 16/15) framing. As an alternative, it finds only the scrambler from the idle fill. | ✅ decodes a live 10.24 kBd IESS-308 carrier to its IBS frames (rate 1/2, differential, V.35) |
| **Carrier ID (DVB-CID, ETSI TS 103 129)**: the spread-spectrum identifier below a carrier. It gives the unique ID (and MAC) of the uplink modulator, the position, the telephone number and text. | ✅ to the specification, on synthetic carriers (there is no CID in the recordings yet) |
| **Comtech CDM modems** (one decoder entry). DecSAT finds the type: TPC 2964, K = 7 Viterbi or FastLink from the first look, and the model from the data. As an alternative, you select the type: CDM-600L voice (TPC → D&I++ → G.728), CDM-570L TPC (→ IP / TS), CDM-570L Viterbi, or CDM-570L trunk (voice + IP with ADS-B and radar). DecSAT plays the G.728 voice in each channel when it finds speech. You do not push ▶. Thus you can hear several carriers at the same time, or one voice at a time if you prefer. | ✅ on live CDM-600L and CDM-570L carriers |
| **IBS programme audio → apt-X**. IBS at n × 64 kbit/s carries the Standard apt-X (apt-X 100) of a studio link. IBS (IESS-309) has G.704-shaped frames below the IBS synchronous scrambler, x¹⁵+x¹⁴+1, which restarts every 128 frames. This was found from the signal. DecSAT finds the codeword alignment, the stereo and the AutoSync word blind. You can listen and record a `.wav`. The 0–4 kHz band decodes exactly. The 4–16 kHz band uses step-size tables fitted to the carrier, because the tables of Standard apt-X are not published. | 🟡 on a live 256 kbit/s Comtech IBS carrier: stereo 32 kHz, full band (upper bands approximate) |
| **Enhanced apt-X in a transport stream**: the contribution feed of a broadcaster. The stereo programmes are private streams (stream type 9Bh, private data indicator `APTx`, 576 kbit/s each). The audio is 24-bit Enhanced apt-X at 48 kHz. Its framing and codeword packing were found from the stream. It is the decoder of aptX HD with the two last bits of the upper bands carried as parity. The programme list names the services. **Play in the app** plays them (the app decodes them, without ffmpeg). `aptx_wav` writes each service to a `.wav`. | 🟡 on a recorded Ku-band multiplex (six services, bit-exact against FFmpeg's aptX HD on repacked vectors). The in-app player is not yet tried on a live carrier |
| **E1 voice**: G.704 E1 or Comtech Drop & Insert++ timeslots, G.711 A-law. Levels for each channel, listen, record `.wav`. DecSAT also finds and decodes G.728 LD-CELP 16 kbit/s voice in two bits of a timeslot. One timeslot can hold a maximum of three such channels. | ✅ (G.728 confirmed on live CDM-600L and CDM-570L voice) |
| **Radar feeds** on CDM-570/570L links. Track reports in IBM bisync blocks. **ASTERIX** categories 034 and 048 in HDLC (DecSAT also reads the Mode S registers in them). ADS-B (category 021) in IP. The outputs are a track table, a CSV log and the **radar scope**. The radar scope is a PPI with trails and leaders, a map, airports and runways. It shows ADS-B aircraft on the picture of a radar. Callsigns come from a decoded ADS-B feed or, when you set it to on, from adsb.lol. | ✅ on live carriers |
| **Radar station monitoring** (an RCMS multicast in Frame Relay on a CDM-570L trunk). It shows the units of the station and the points that they report, adjacent to the scope. | ✅ on a live trunk (the meaning of the points is not known) |
| **Generic PSK/APSK/QAM → symbols** (`.bin`, one byte for each symbol), BPSK…32APSK and 8/16/64QAM, for non-DVB carriers. On BPSK and QPSK, it also looks for a convolutional code, as the Viterbi decoder does. It stops this search after some time. If it finds a code, it decodes the result through the payload search. If not, it tells you that there is none (*a block code or uncoded*). | ✅ |
| **TDMA bursts**: one carrier or a full MF-TDMA group in a VFO. DecSAT finds and demodulates the bursts one by one. It reads the layout of the bursts blind (preamble, pilots, fixed fields, idle fill). It finds the slot grid, the frame and the terminals. It looks for a rate-½ convolutional code in the data of the bursts. It shows a burst map. It writes the data symbols of each burst to a `.bursts` file. **SCPC or TDMA** is a setting of each VFO (and of new VFOs). The waterfall finds bursty bands apart from the continuous carriers. | ✅ analyser and demodulator on a live 3-carrier group. The coding inside is the subsequent task |
| **IS-19 DAMA outbound → packets and call signalling**: the 102.4 kBd QPSK outbounds of a DAMA telephony network on Intelsat 19. The vendor is not known. The frame, the pilots, the scrambler and the packet stream were all measured from a recording. DecSAT finds the frames and reads them in the correct orientation. It corrects carrier slips from the pilots. It descrambles the packet stream. It finds the **request acks** and the **channel assignments**. An assignment goes out ~0.4 s before the two carriers of a call key up. Record writes each packet to a `.csv`. | ✅ on a live recording: each call set-up in it, to the millisecond |
| **Satellite beacons**. DecSAT tracks and measures the carrier: frequency (absolute, with the LO), drift, C/N0 and level, on charts. It finds telemetry on the carrier blind. The telemetry can be a data subcarrier that phase-modulates the carrier (PCM/PSK/PM), data directly on the phase (PCM/PM) or a suppressed carrier (BPSK/QPSK). It can be NRZ or bi-phase. DecSAT finds minor frames on the sync words of IRIG 106, the marker of CCSDS or a word found blind, in any polarity or differential coding. It finds the minor-frame counter. It shows the major frame as a map of which words change, and plots any word against time. It decodes CCSDS Reed–Solomon (dual basis, interleaved), the randomiser, the K = 7 code and TM/AOS transfer frames. A pointing tone rises with the level. DecSAT writes the frames and the log of the carrier to files. | ✅ on live beacons. Intelsat 19: 4800 bit/s bi-phase on a 48 kHz subcarrier, IRIG frames. Eutelsat 172B: 9600 symbol/s NRZ on a 76.8 kHz subcarrier, K = 7 coded CCSDS TM frames, every frame |
| **Inmarsat Classic Aero → ACARS, ADS-C, voice**: the L-band aeronautical service on a VFO. DecSAT names the channel from the signal. The channels are the P channel (ground to aircraft, 600, 1200 or 10500 bit/s), R and T channel bursts (aircraft to ground) and C channel telephone calls (8400 bit/s AMBE, 21000 bit/s 9.6 kbit/s MP-LPC). DecSAT shows the signalling in words, reads ACARS messages with ADS-C positions and plays the voice. This is the receiver of [DecAero](https://github.com/CasualArclamp/DecAero), built in. | ✅ on recordings: P channels at 600, 1200 and 10500 bit/s with ACARS, and a 21000 bit/s call. Bursts and 8400 bit/s voice work in DecAero and are not yet tried here |
| **Inmarsat GMR-2+ (IsatPhone) → sync, System Information**: the 50 kHz forward control carriers of the satellite phone network of Inmarsat, on a VFO. DecSAT decodes the sync channel (spot-beam colour codes, frame number) and the broadcast System Information (network, location area, neighbour beams, timing, the beam map). The coding was found from recordings. It is not in the GMR-2 specification. | ✅ on a recording of channel 88: all the sync and broadcast blocks decode, with a few exceptions |
| **QO-100's PSK beacon** (the uncoded format of AO-40, 400 bit/s): frames with CRC, the blocks as text, and housekeeping values when the beacon sends them. Also from a sound card in the small `qo100-beacon` app. | ✅ on WebSDR recordings of 10489.750 MHz: the CRC of each frame is good, and the FEC block after each frame decodes |
| Narrow carriers: VFOs down to 500 Hz. ~10 kBd SCPC carriers lock. DecSAT coasts through short bursts that fall on a carrier (Bluetooth that leaks into the HackRF). | ✅ |
| IQ recorder and spectrum-only VFOs. | ✅ |
| IQ file replay (`cs8`, `cu8`, `cs16`, `cs24`, `cf32`; two-channel `.wav` from SDR#, HDSDR, SDRuno, SDR++ with the format, rate and centre from the header). DecSAT reads the rate and the centre from file names. | ✅ |
| **Live HackRF One**, 2–20 MS/s, pure Rust over USB (no DLLs), LNB LO. An input-level warning shows when the gain is too high. | ✅ |
| **Live Fobos SDR** (RigExpert), 8–50 MS/s, 14 bits. DecSAT loads the library of RigExpert at run time (agile or stock firmware). The waterfall, VFOs, retuning and decoders are the same as for the HackRF. | ✅ used on a real board under Windows, DVB-S2 TS and IP carriers at 20 and 50 MS/s |
| **Live Airspy Mini / R2**, 3/6 MS/s (2.5/10 on an R2), 12 bits, 24–1750 MHz. Pure Rust over USB (`libairspy-rs`, no DLL). Bias tee on request. | ✅ tested live: a Mini at 6 MS/s (QO-100), an R2 at 10 MS/s |
| **Live ADALM-PLUTO / Pluto+ / LibreSDR**, 0.26–61.44 MS/s, 70 MHz–6 GHz. Pure Rust over USB or the network (no libiio, no DLL). 8-bit IQ on the Tezuka firmware. Receive only. | ⚠️ tested against a simulated Pluto only. Not yet tried on hardware |
| **📷 Snapshots** of the spectrum and waterfall (or the window) to PNG, with a caption. **Session log** to CSV. **PCAP in parts** for tools that read completed captures. DecSAT **names the satellite** from the orbital position that a NIT or an RCS map signals. | ✅ |
| **Network IQ**: raw IQ from a different program. Thus any radio that the program controls operates (for example, an SDRplay RSPduo under SDR++), on Windows or Linux. The sources are the IQ Exporter of SDR++, the TCP/UDP sinks of GNU Radio, and rtl_tcp (recognised and tuned). `tcp://` connects, `listen://` waits for a sender, `udp://` binds. The formats are int8, uint8, int16, int32 and float32. You enter the rate, the frequency of the sender and the LNB LO, because the stream carries none. | ✅ on simulated carriers over TCP and UDP |
| **LDPC + BCH → BBFRAMEs**: all 21 S2 and 31 S2X codes, BBHEADER, stream info, payload rate. | ✅ |
| **S2X**: 8-bit PLS code, all 55 normal/short MODCODs, from 2+4+2 8APSK to 256APSK, the new interleavers. | ✅ |
| **S2X VL-SNR**: the VL-SNR header, pi/2-BPSK (and spread), medium FECFRAMEs, all 9 MODCODs. It decodes down to approximately 0 dB Es/N0 at this time. | ✅ |
| PL scrambling: DecSAT finds the preferred sequences of S2X Table 19e from the pilots. | ✅ |
| **S2X baseband**: the low roll-offs (0.15/0.10/0.05, signalled by RO that alternates with `11`), GSE-HEM (GSE sliced across BBFRAMEs) and GSE-Lite. DecSAT reads **multistream** carriers stream by stream. Each ISI goes to its own stage: GSE, GSE-HEM, a transport stream, or transport packets in a generic stream (the signalling of a VSAT hub). | ✅ live on the S2X ACM outbound of a Newtec hub (0.05 roll-off, signalling on ISI 0, IP on ISI 1). GSE-HEM on test signals |
| **S2X superframing** (Annex E). DecSAT finds super-frames by their start sequence and reads their format. It decodes formats 0 (S2X) and 1 (S2 legacy) with the super-frame pilots on or off. It names the other formats. | ✅ on test signals (none seen live yet) |
| **ACM terminal table**. For each GSE label (the MAC of a terminal), the table shows its bytes, its IP addresses and the MODCODs in which the hub sends its data. This is the link of the terminal as the hub sees it. | ✅ live: 25 terminals of a hub, QPSK 5/6 to 16APSK 5/6 |
| **DVB-RCS signalling** in the outbound of a hub (EN 301 790 / 545-2): the forward and return links of the RCS map, the network clock (NCR), the terminal information, the superframe/frame/timeslot plans, and the burst time plan and corrections when the hub sends them. It also shows the rate of each signalling table, and those of the vendor are included. | ✅ live (RCS2 over GSE: its PDU types named only) |
| **Return pools** (the *Return pool* decoder of TDMA mode). It shows the layout of the pool over time, as a hub changes the size and the position of the carriers of its terminals. It shows the slot and frame grid of the bursts of the pool. DecSAT ties the grid to an outbound VFO whose signalling keeps the same time. | ✅ live: 5.025 ms slots in a 40.200 ms frame, which agree with the 40.2 ms table of the outbound |
| **A Newtec hub's burst plan** (its private table D1h, found from a capture; there is no public spec). It shows each burst that each terminal can send, frame by frame: slot, length, frequency and bandwidth. DecSAT learns the bandwidth from how the hub packs the bursts. It also shows the shares of the terminals, and the plan aligned on the band of a Return pool VFO. | ✅ live: 24 terminals, 16.7 bursts a 40.2 ms frame. The plan fits the spectrum of the pool at 0.97 |
| **A hub's inroute signalling in GSE** (non-IP PDUs, found from a capture; there is no public spec). It shows the clock of the hub, its inroutes (uplink frequency, symbol rate, slot length, modulation) and a burst time plan for each inroute every 125 ms. On a Return pool VFO, DecSAT uses the plan to demodulate the burst of each slot: 8PSK, MER, carrier and timing for each terminal. | ✅ on a 172B capture: 4 inroutes on the pool, ~3300 bursts a second, 97 % demodulated, 184 terminals |
| **GSE → IP → PCAP** + live IP stats. DecSAT marks flows that are encrypted in transit. It detects the GSE variant from the data. | ✅ |
| **MPEG-TS**: services, PIDs, errors. The outputs are a `.ts` file, UDP, and TCP/HTTP to VLC or PotPlayer. | ✅ |
| **TS analyser** (EBSPro-style): PIDs, services, now/next, network, tables. | ✅ |
| **BISS descrambling** (DVB-CSA, BISS mode 1). You type the key in the analyser or in the VFO panel. DecSAT checks the key against the stream and keeps it for its carrier. Each output is then clear. | ✅ on a live BISS contribution feed (Ericsson, 8PSK 3/4). Bit-exact against the CSA of VLC in the two directions |
| **In-app TV player**. ffmpeg decodes a service of the TS (H.264 incl. interlaced, MPEG-2, HEVC, VVC, and AV1 in AOM's TS mapping; MP2/AAC/AC-3…). The player deinterlaces the pictures. The sound goes through the audio of the app. The sound gives the timing of the pictures. | ✅ on the same live feed: 1080i25 H.264, three MP2 tracks |
| **Multicast TV in IP**. DecSAT finds an MPEG-TS carried in UDP inside GSE (bare, RTP, or behind a header of the sender). It analyses and plays this TS as the TS of a carrier. | ✅ on a recording of the BBC News multicast of Eutelsat 172B (6-byte header) |
| **Multicast audio** from GSE or MPE: SAP/SDP names and codecs. DecSAT describes unannounced RTP AAC and Opus from their packets. It reassembles IPv4 fragments. It shows now-playing messages. You can play a stream in the app (volume, pause) or in VLC/PotPlayer, and record it to a file. | ✅ checked on a recording of a live MPE radio multiplex |
| Modulator (HackRF TX / IQ file). | M6 |
| **Transmitter app** (`decsat-tx`). It encodes a webcam and a microphone live in H.264, H.265, H.266 or AV1 (GPU or CPU). It has QO-100 presets from the BATC bandplan. The output is the HackRF or an IQ file. | ✅ every codec from a webcam, checked by IQ file and by the receiver of DecSAT. Not yet on the air |

## Signal galleries

The signal gallery shows how each kind of carrier looks on the waterfall,
in the constellation and against time, live and side by side. It shows:

- DVB-S2 with constant and adaptive coding, and DVB-S.
- NovelSat NS3/NS4, TPC 2964, Q-Flex FastLink and K = 7 Viterbi links.
- TDMA and STDMA bursts, and Comtech 8PSK.
- Beacons and CW.
- The artefacts of the HackRF.
- Codes that no program decodes yet.
- DVB-CID, and transponders wider than the receiver.

Each card tells you how to identify the signal and what DecSAT does with
it. Each card gives the numbers measured on these carriers.

[`docs/signal-gallery.html`](../signal-gallery.html) is one self-contained
page. Download it and open it in a browser, or
[view it rendered](https://htmlpreview.github.io/?https://github.com/CasualArclamp/DecSAT/blob/main/docs/signal-gallery.html).
An Es/N0 slider sets the noise in each pane. Pause stops the panes. The
"Retune" button of the HackRF card shows how spurs move with the tuning
while real carriers stay in position.

[`docs/rcs-field-guide.html`](../rcs-field-guide.html) does the same for
satellite return links: DVB-RCS, the DVB-RCS2 burst kinds and the two
vendor returns measured on 172B. For each link it shows the pool
waterfall, the envelope of one carrier, the layout of the burst and its
constellation. It also has a table that tells you how to tell the return
links from the outbound
([view it rendered](https://htmlpreview.github.io/?https://github.com/CasualArclamp/DecSAT/blob/main/docs/rcs-field-guide.html)).
